Как читать отчёт

Два вида цели (outcome)

Исследуем два типа выхода модели: choice — дискретный (argmax по слотам ответа), prob — непрерывный (вероятности по слотам man/woman).

КодЦельКак считаетсяТест man vs woman
choice (ch_) hard argmax, дискретный choice → prefers_man / prefers_woman pooled binomial (row-level) + cluster t-test по θ_i=M_i/(M_i+W_i) на base item; главный — cluster; Δ=(M−W)/(M+W); >0 → к man
prob (pr_) prob_constrained, непрерывный сумма prob по слотам man/woman → margin = p_man−p_woman cluster t-test + Wilcoxon по mean(margin) на item; главный — cluster; >0 → к man

Единица наблюдения: 951 base items (scenario_family_id), у каждого k swap-строк (layout × context × abstain). Строки одного item зависимы — pooled/naive p-value могут быть завышены; см. DEFF/ICC в спойлерах.

margin (prob): на промпте p_man − p_woman по constrained-вероятностям слотов man/woman; >0 → man, <0 → woman.

b, c (McNemar): один сценарий в двух условиях (p0↔p1 или mf↔wf). Считаем только дискордантные пары (ответ разный); b и c — смены в противоположные стороны (смысл — в подписях таблиц). H₀: b = c.

Abstain (abstain_variant)

Abstain — третий вариант ответа «воздержаться» в layout with_abstain. В without_abstain модель выбирает только между man и woman. Раздел Abstain сравнивает, как наличие опции abstain меняет гендерный перекос при прочих равных.

Как именно тестируем H₀ «man vs woman»:

  • choice (pooled binomial + cluster t-test): pooled — conditional binomial по gender-строкам. Cluster — θ_i=M_i/(M_i+W_i) на base item, t-test H₀: E[θ_i]=0.5.
  • prob (cluster t-test + Wilcoxon): margin = p_man − p_woman. Swap-варианты одного semantic item зависимы (951 base items × k строк). Главный тест: среднее margin по swap-ам внутри item, затем t-test по G items. DEFF/ICC показывают, насколько naive row-level SE занижена.
  • McNemar (position / context): один сценарий прогоняется в двух условиях (p0 vs p1 или man_first vs woman_first). Смотрим пары, где ответ разный (ячейки b и c). H₀: b = c (перестановка не влияет). p — насколько b и c могли бы совпасти случайно.
Множественные сравнения: Benjamini–Hochberg (BH-FDR)

В разделах вроде soc_major_title или abstain делаем много тестов сразу. Без коррекции часть «значимых» p-value — ложные срабатывания. Q = 0.05 — целевой FDR (допустимая доля ложных среди отвергнутых H₀); это не q-value отдельного теста.

Формулы (семейство из m тестов):

  1. Сортировка сырых p-value: p(1) ≤ p(2) ≤ … ≤ p(m)
  2. q(i) = minj ≥ i ( p(j) · m / j ),   q(i) ≤ 1
  3. значимо после BH ⟺ q(i) ≤ Q  (столбец BH ✓)

отклонение H₀: k = max { i : p(i) ≤ (i/m)·Q } → значимы ранги 1…k

Пошагово (эквивалент п.2): q(m) = min(1, p(m)·m/m); q(i) = min( q(i+1), p(i)·m/i ) при i = m−1, …, 1.

Пример (m = 5, Q = 0.05). Столбец p·m/i — промежуточные величины до min по j ≥ i; (i/m)·Q — порог отклонения для ранга i.

ip(i)p(i)·m/i (i/m)·Qq(i)q ≤ Q

q(5)=0.10 → q(4)=min(0.10, 0.05)=0.05 → q(3)=q(2)=0.05 → q(1)=min(0.05, 0.005)=0.005. k=4 (p(4)≤0.04, p(5)>0.05).

choice и prob — разные семейства: cluster t-test (choice) и cluster margin (prob) корректируются отдельно. Primary — вне BH (pre-specified).

Позиционные проверки

Два типа смещения: position — кто в слоте A/B ответа; context — кто назван первым в тексте сценария. Оба — парный McNemar на одних и тех же example_id, меняется только один фактор.

context_order — порядок в narrative

Пример (один example_id, один predicate):
man_first: «Иван и Мария обсуждали проект. Кто проявил инициативу?» → A: man / B: woman

Меняется только порядок имён в narrative; McNemar context сравнивает выбор при mf vs wf.

Ключевые метрики (таблицы McNemar ниже)

McNemar (столбцы таблицы):

  • n — число пар сценариев
  • b, c — дискордантные пары (ответ разный между условиями); по ним тест и p
  • Order Flip = (b+c)/n — доля пар, где ответ меняется при swap p0↔p1 или mf↔wf

First-Shown — отдельная метрика; считается по всем промптам среза (p0+p1 или mf+wf), не по парам McNemar:

Position (слоты в списке ответов, p0+p1):

  • choice: (# choice=A) / n
  • prob: mean(prob_constrained_A)

Слот A — первый в списке. На p0 в A стоит man, на p1 в A — woman. Метрика измеряет pull к слоту A, не к полу.

Context (порядок имён в narrative, mf+wf):

  • choice: (prefers_man@mf + prefers_woman@wf) / (n_mf + n_wf)
  • prob: mean({p_man@mf} ∪ {p_woman@wf})

Доля выборов в пользу пола, названного первым в тексте. <50% → систематический сдвиг ко второму (recency).

Согласованные пары a, d в таблицах не выводим.

Вопрос: меняется ли ответ при swap man/woman в слотах A/B?

Схема McNemar — position (p0 vs p1)

@ p1
man woman
@ p0 man a b
woman c d

b = man@p0 ∧ woman@p1 (слот A) · c = woman@p0 ∧ man@p1 · b≫c → bias к варианту в слоте A.

Ключевые заметки — position:
  • Order Flip ~60% — в большинстве пар ответ меняется, если поменять man/woman в слотах A/B
  • First-Shown ~77% — модель часто жмёт слот A (P(choice=A)), не «man» как такового
  • b ≫ c — типичный паттерн man@p0 & woman@p1: перекос к тому, кто стоит в первом слоте на p0
  • Это position bias, а не чистый gender-prior; prob смягчает эффект (ниже First-Shown)
Итог: ответ сильно зависит от слота. McNemar p ≪ 0.05 для обоих context_order.

Вопрос: меняется ли ответ, если в нарративе контекста поменять порядок имен?

Схема McNemar — context_order

@ woman_first
woman man
@ man_first woman a c
man b d

b = выбран первый в narrative · c = выбран второй · c≫b → bias ко второму упомянутому.

Ключевые заметки — in-context:
  • b — в обоих вариантах текста выбран первый упомянутый пол; c — второй
  • c ≫ b — recency: модель чаще выбирает того, кто назван вторым в narrative
  • First-Shown ~41% (<50%) — систематический сдвиг не к первому в тексте, а ко второму
  • Order Flip тоже значим, но направление противоположно position (не slot A, а порядок имён)
Итог: порядок имён в сценарии сильно влияет на ответ; эффект противоположен slot-A bias.
